# 实验批次记录模板（Batch Record）

> 每次提交一批实验（或重跑一个口径）前填。目的：批次之间可区分、口径变更可追溯、结果不会张冠李戴。

```markdown
## 批次
- 批次名/前缀：
- 提交时间（含时区）：
- 提交方式（脚本名/命令）：

## 口径定义（本批次唯一，写死）
- 实验矩阵面：      # 主实验 / 消融 / tuning / screening / 其他
- 模型 / 算法 / 噪声档 / 分布：
- 种子（固定 or 随机，哪些）：
- 超参与轮数预算（每一阶段）：
- 基线来源（复用/新跑，provenance 链接）：

## 与上一批次的关系
- 相对旧批次的改动（代码 commit / 配置变化）：
- 旧批次去向（归档路径 + 弃用说明文件）：
- 新旧是否可比（不可比则旧数据不得混用）：

## 资源与调度
- 资源核查（显存/队列/在飞任务）：
- 预计耗时、并发策略：

## 进度与结果
| cell | 状态 | 结果值 | 结果文件路径 |
|---|---|---|---|
|  |  |  |  |

## 判读
- 主指标与判据（哪个口径决定成败，判据代码能给两条分支吗）：
- 结论与下一步（等谁拍板）：

## 善后
- 结果回填清单（表格/图/文档/PPT——单一事实源下游全部列出）：
- 清理项（临时文件/僵尸任务/残留目录）：
```

## 使用要点

- "口径定义"一节是批次身份证：任何数字引用都必须能报出这一节的完整内容
- 复用别处跑出的 cell 必须写 provenance（来源批次/运行号/配置哈希），否则按污染处理
- 结果全部落地后再统一回填下游，避免"半截图"状态长期存在
