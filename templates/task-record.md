# 任务记录模板（Task Record）

> 每完成一个任务/排查，把这份模板填完。目的：任何结论可复现、副作用可追溯、状态可交接。

```markdown
## 任务
- 标题：
- 关联（issue/任务号/commit）：

## 环境与版本
- 环境栈（生产/测试/本地）： 
- 分支/镜像/代码版本：
- 时间窗（含时区）：

## 问题
- 现象（错误原文）：
- 澄清确认过的事项（环境/时间/重试）：

## 证据链
| 层 | 证据来源 | 关键记录（文件/命令/ID） |
|---|---|---|
| 入口 |  |  |
| 业务 |  |  |
| 数据 |  |  |
| 对端 |  |  |

- 根因（一句话 + 代码路径/记录佐证）：

## 修改
- 改了什么（文件/配置/方式——必须走正规路径）：
- 测试（先红后绿，测试名）：

## 验证
- [ ] 单元
- [ ] 集成
- [ ] 端到端/真机（真实路径描述）
- [ ] 否定断言也有证据（不受影响的部分怎么证明的）

## 副作用记账
（排查本身产生的记录/费用/残留/新建实体，以及清理情况）

## 沉淀
- #lesson 条目：
- 需要更新的文档/记忆：
- 遗留事项与建议下一步：
```

## 使用要点

- "根因"必须能反查到证据行；写不出证据链的根因 = 还没查完
- 副作用记账是硬要求：探测写审计日志、真实调用产生上游费用、残留监听端口，都算
- 遗留事项单独列出，等用户拍板，不擅自动手
