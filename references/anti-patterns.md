# 反模式与真实教训（Anti-Patterns）

> 每个反模式都来自真实事故，附"当时的后果"与"正确的做法"。格式：**现象** → **后果** → **正解**。

## 1. 提交批量任务前不看资源占用

- **现象**：集群同时提交 80 个训练任务，没查 GPU 显存；另一项目的推理服务正占着 30/32 GiB。
- **后果**：实验任务全部 OOM；更糟的是训练脚本吞掉异常后仍正常退出、Ray 标记"成功"——38 个假成功结果。
- **正解**：批量提交前必查资源（显存/队列/端口）；被吞掉的异常比崩溃更危险，任务状态必须与日志互证。

## 2. 只看任务状态，不看日志尾部

- **现象**：`except Exception` 把训练崩溃吞掉，进程 exit 0。
- **后果**：平台标记 SUCCEEDED，38 个全是垃圾结果；后续分析全建立在假数据上。
- **正解**：判完成 = 状态 + 日志无 traceback；异常处理要"记痕并失败"（写入错误状态/非零退出），不要静默。

## 3. 用裸 SQL / 直接改文件绕过正规路径

- **现象**：直接 UPDATE 数据库改模型能力配置。
- **后果**：绕过版本号 CAS、运行时缓存自增和审计——配置改了但线上读的还是旧缓存，且没有任何留痕，后续排查全部失真。
- **正解**：改配置走管理 API/界面，让校验、缓存失效、审计在正规路径上发生；"为什么必须走 API"写进文档。

## 4. 改共享文件前不 fetch 对比

- **现象**：基于旧版本 AGENTS.md（约定文件）写改动并直接提交；远端已有别人刚推的同文件新规则。
- **后果**：一次提交把协作者的规则改动整体回退。
- **正解**：动共享文件前先 `git fetch` + 对比；基于最新版做最小增量；提交前核对 `@{u}` 领先/落后。

## 5. 拿到含糊问题报告直接开跑

- **现象**：只有一张截图、一句"这个坏了"，没有环境、时间、错误文本。
- **后果**：在错误环境/错误时间窗里空转数小时，被追问"你在干什么？我只是让你检查一下"。
- **正解**：先要环境 + 时间点 + 错误原文三件套；没有就明确说"信息不够，需要 X"。

## 6. 用记忆代替硬证据

- **现象**："这个应该没变 / 那次肯定没改生产"。
- **后果**：否定陈述没有 git/mtime/日志佐证时，等于没说；曾经因此漏掉真正的改动源。
- **正解**：任何断言（包括"没动过"）都要能给出佐证命令与输出；拿不出证据就重新查。

## 7. 改数据只改一处

- **现象**：实验口径变了，正文数字回填了，图表 PNG 没重生成；或者图注与正文数字不一致。
- **后果**：图文不一致，编译出的 PDF 自相矛盾；审稿/面试被问穿。
- **正解**：数字单一事实源 + 每个下游（表格、图、摘要、PPT）列为受影响的必改清单；提交前做一致性扫描。

## 8. 合并/上线任务擅自扩大操作

- **现象**：合并分支时自作主张做了临时 worktree 重放、双向 diff 取证、amend 改写、强推。
- **后果**：工作过度，历史被改写，用户明确叫停。
- **正解**：合并任务只做合并 + 解决冲突；冲突语义不明就停下来报告，把取舍交还用户；不重放不改写历史。

## 9. 把"设计如此"当"实测如此"

- **现象**：训练结束时无条件恢复"干净标签验证集选出的最优 checkpoint"并覆写末轮值，论文却写"final-round accuracy"。
- **后果**：口径不实：与基线（无选模）不对称；与"标签不可中央审计"的前提自相矛盾。
- **正解**：上报数字前先审计代码路径（最终值从哪来、有没有选模/恢复/早停）；每类算法标注选模规则；知乎上能追到的问题都主动披露。

## 10. 轻信对端/下游的状态透传

- **现象**：上游用 HTTP 200 包着业务错误信封（"Content-Type 不支持"），平台把 200 当成功，任务变"僵尸 running"。
- **后果**：错误被吞，库里只剩无意义的通用失败状态，几天后发现。
- **正解**：对端返回 200 也要校验响应体契约（业务 code、必需字段）；透传的错误字段不能丢，要落库可查。

## 11. 改测试来"消红"

- **现象**：CI 红是因为测试环境缺某个 API（如 jsdom 无 clipboard），有人选择改断言或删测试。
- **后果**：覆盖变弱，真回归漏网。
- **正解**：先归因——是产品 bug 还是测试基础设施缺失；后者修基础设施（stub/setup），不改被测代码和断言。

## 12. 临时产物不清场

- **现象**：调试用监听端口、探针脚本、死任务留在环境里。
- **后果**：残留端口占用、僵尸任务占着并发额度、后续排查被"别人的痕迹"干扰（时间戳早于我的首跑）。
- **正解**：排查/实验结束即清理并复核；判断残留看资源 ID 与时间戳，不只数行数。

## 通用判别式

遇到"要不要按某个约定做"的犹疑时，问三句：

1. **证据**：这个说法/数字，我拿得出复现命令和原始记录吗？
2. **回归**：如果有人把这次改动回滚，哪一行测试会先红？
3. **记账**：这件事做完，会留下什么痕迹/费用/残留物？清单写得出来吗？
